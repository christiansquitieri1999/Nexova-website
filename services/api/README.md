# Nexova incidents API

Local Python standard-library service that analyzes Nexova support-ticket CSV files using the
privacy-safe rules in [`scripts/analyze.py`](../../scripts/analyze.py). It returns aggregate metrics
only: customer email addresses and source rows are never included in responses or logs.

## Run

Python 3.11 or newer is recommended. From the repository root:

```bash
python services/api/api.py
```

The service listens on `http://127.0.0.1:8000`.

CORS is restricted to `http://localhost:3000`. Set `NEXOVA_CORS_ORIGIN` before starting the service
when the backoffice uses another origin:

```bash
NEXOVA_CORS_ORIGIN=https://backoffice.example.com python services/api/api.py
```

## Endpoints

### `GET /health`

Returns service availability.

### `POST /api/incidents/analyze`

Accepts a UTF-8 CSV file in `multipart/form-data`. The file part must be named `file`:

```bash
curl -F "file=@../../info-nexova/incidents-nexova.csv" http://127.0.0.1:8000/api/incidents/analyze
```

The body limit is 5 MB. A successful response contains totals, invalid-rule counts, category and
status counts, percentages, and satisfaction-score aggregates. Invalid requests return `4xx` HTML
responses with a descriptive message and without echoing CSV content. Missing files and invalid
CSV content return `422`; unsupported file types or request content types return `415`.

### `GET /api/incidents/results/exports`

Downloads the most recent successful analysis as a two-column CSV using
`Content-Disposition: attachment`. The in-memory result is replaced by each successful analysis and
is cleared when the service restarts. Before any successful analysis, the endpoint returns a
descriptive `404` HTML response.

```bash
curl -OJ http://127.0.0.1:8000/api/incidents/results/exports
```

## Supplier Directory API

The TinyDB-backed Supplier Directory runs separately from the incidents service, on port `8001`.
Its files are `supplier_api.py`, `supplier_store.py`, and `supplier_models.py`; the default database
is `db/suppliers.json` relative to this directory. Start it from `services/api/`:

```bash
python supplier_api.py
```

The service currently binds to `0.0.0.0:8001` and allows the backoffice origin
`http://localhost:3000`. API responses are JSON. Supplier creation validates the request and
returns `422` for schema/business-rule errors; missing IDs return `404`. Status values are `active`
and `suspended`; `monthly_rate` must be greater than zero. Currency must match country (Spain/EUR,
USA/USD). `updated_at` is generated by the service and refreshed when the rate is changed.

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/suppliers?country=Spain&category=job_boards` | List suppliers; either or both filters are optional. |
| `POST` | `/suppliers` | Create a supplier; returns the record including its ID. |
| `GET` | `/suppliers/{id}` | Read the complete supplier record. |
| `PATCH` | `/suppliers/{id}/rate` | Update `monthly_rate`; body: `{"monthly_rate": 1200}`. |
| `PATCH` | `/suppliers/{id}/status` | Change status; body: `{"status": "suspended"}`. |
| `DELETE` | `/suppliers/{id}` | Delete a supplier. |

Supplier categories are `job_boards`, `ats_software`, `assessment_tools`, `training_platforms`,
`payroll_and_hr_software`, `video_interview`, `background_check`, `office_and_facilities`, and
`it_and_software_licenses`.

## Centralized Incident Manager data model

Incident payload validation lives in `incident_models.py` and uses the canonical Nexova values:

- Categories: `technical_failure`, `process_error`, `client_complaint`, `candidate_issue`,
  `staff_issue`, `sla_breach`, `data_quality`, and `other`.
- Origins: `customer`, `branch`, and `internal`.
- Branches: `central`, `valencia_operations`, `miami_office`, and `remote`.
- Statuses: `open`, `in_progress`, `resolved`, and `discarded`.

New incidents accept `title`, `description`, `category`, `origin`, and `branch`. The service assigns
the unique ID, sets the status to `open`, and creates both UTC timestamps. Persisted records also
include `status`, `created_at`, and `updated_at`; clients cannot override server-controlled fields.

Valid status transitions are `open` to `in_progress` or `discarded`, and `in_progress` to `resolved`
or `discarded`. `resolved` and `discarded` are terminal states. The separate seed model accepts a
historical creation date and mapped status for the one-time CSV import.

The HTTP service exposes the following authenticated management operations on port `8003`:

| Method | Path | Purpose |
|---|---|---|
| `POST` | `/api/incidents` | Register an incident; returns `201` and assigns `open` status. |
| `GET` | `/api/incidents` | List incidents with optional `status`, `origin`, `branch`, and `category` filters. |
| `GET` | `/api/incidents/{id}` | Return one incident; missing IDs return `404`. |
| `PATCH` | `/api/incidents/{id}/status` | Advance status with lifecycle validation; invalid transitions return `400`. |
| `GET` | `/api/incidents/summary` | Return totals by status, category, origin, and branch. |

Start it from the repository root with `python services/api/incident_api.py`.

Seed the historical CSV from the repository root with:

```bash
python scripts/seed_incidents.py
```

The seed reads `info-nexova/incidents-nexova.csv`, rejects the 4 invalid source rows, reports them,
applies BRIEFING transformations, and skips records already seeded. Running it repeatedly does not
duplicate incidents.

## Password recovery API

The User & Profile API on port `8002` exposes:

- `POST /auth/forgot-password` — accepts `{"email":"person@nexova.com"}` and always returns `200`
  without revealing whether the account exists.
- `POST /auth/reset-password` — accepts `{"token":"...","new_password":"..."}` and returns `400`
  for invalid, expired, or previously used reset tokens.
- `POST /auth/change-password` — accepts `{"current_password":"...","new_password":"..."}` and
  requires a valid session bearer token; it returns `400` when the current password is wrong.

Configure password recovery with these environment variables:

| Variable | Required | Purpose |
|---|---:|---|
| `SECRET_KEY` | Yes | Existing HMAC key for session JWT signing; reset tokens use `RESET_TOKEN_SECRET` when set |
| `RESET_TOKEN_SECRET` | Yes | Dedicated HMAC key for password-reset JWT signing |
| `RESEND_API_KEY` | Yes | Resend API key used to send reset emails |
| `RESEND_FROM_EMAIL` | Yes | Verified Resend sender, for example `Nexova <passwords@your-domain.com>` |
| `PASSWORD_RESET_URL` | No | Frontend reset route; defaults to `http://localhost:3000/reset-password` |

Add the values to `services/api/.env` locally. Never commit that file or paste API keys into source
or responses. Use `services/api/.env.example` as the variable-name template.

### Run the User & Profile API

From `services/api/`:

```bash
uv run uvicorn user_api:app --host 127.0.0.1 --port 8002 --reload
```

The FastAPI application provides interactive API documentation at
`http://127.0.0.1:8002/docs`.

### Seed initial suppliers

From `services/api/`, run the installed `seed` command:

```bash
uv run seed
```

It validates and inserts the briefing's initial supplier records into `db/suppliers.json`, skipping
records whose names already exist. The command prints the number inserted; when the database is
already seeded it reports that no records were inserted. It does not clear existing data.
